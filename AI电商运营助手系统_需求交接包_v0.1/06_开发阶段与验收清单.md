# 开发阶段与验收清单

本清单用于控制系统生成顺序。只有当前阶段通过验收，才进入下一阶段。

## 阶段 0：需求复核

- [ ] 已按文档优先级完整阅读需求。
- [ ] 已确认三个角色及权限边界。
- [ ] 已确认 MVP 不连接未知真实 ERP。
- [ ] 已列出页面、数据对象、接口和默认假设。
- [ ] 已说明不在范围内的功能。

## 阶段 1：基础框架与权限

- [ ] 前端、后端、数据库可以本地启动。
- [ ] 配置通过环境变量或安全配置加载。
- [ ] 数据库迁移可重复执行。
- [ ] 存在运营、美工、管理员三类账号。
- [ ] 前端导航按角色显示。
- [ ] 后端接口拒绝越权请求。
- [ ] 管理员未拥有运营角色时不能确认业务结果。

## 阶段 2：项目与商品资料

- [ ] 运营可以新建、编辑、搜索、归档和恢复项目。
- [ ] 商品信息卡支持分组编辑和自动保存。
- [ ] 字段显示数据来源。
- [ ] 缺失字段显示影响范围。
- [ ] 商品卡关键变化会使相关结果显示可能失效。

## 阶段 3：素材、AI 任务与版本

- [ ] 支持商品图、主图、竞品图和参考图上传。
- [ ] 可以选择本次 AI 任务使用的图片。
- [ ] 任务显示排队、运行、成功和失败状态。
- [ ] AI Provider 支持 Mock 实现。
- [ ] 任务保存输入快照、Prompt 版本和输出。
- [ ] 人工编辑产生新版本，不覆盖旧版本。

## 阶段 4：运营内容模块

- [ ] 图片分析区分事实、判断、建议和不确定项。
- [ ] 标题一次生成多个候选并显示关键词、长度和风险。
- [ ] SKU 批量生成并检查重复、歧义和长度。
- [ ] AI 不修改 SKU 编码、库存和价格。
- [ ] 合规检查定位风险原文并显示原因和建议。
- [ ] 高风险内容禁止确认和写回。

## 阶段 5：运营与美工协作

- [ ] 运营可以从图片分析生成改图需求单。
- [ ] 需求单包含目标、修改项、文案、禁改项和验收标准。
- [ ] 运营可以将任务分配给一个美工。
- [ ] 美工只能查看自己的任务和必要商品信息。
- [ ] 美工可以提问、更新状态和上传多版结果。
- [ ] 运营可以通过或退回修改。
- [ ] 任务状态和所有设计版本可追溯。

## 阶段 6：知识、规则与结果

- [ ] 管理员可以维护 Prompt 版本和启停状态。
- [ ] 管理员可以维护合规规则及版本。
- [ ] 运营可以使用模板并提交优秀案例。
- [ ] 最终结果页汇总当前最终版本和风险。
- [ ] 支持 Markdown 报告导出。
- [ ] 导出内容与页面最终版一致。

## 阶段 7：ERP 接口预留

- [ ] 存在统一商品模型。
- [ ] 存在 ERPConnector 契约及能力声明。
- [ ] 核心业务模块没有厂商私有字段。
- [ ] 提供 Mock ERP 或 CSV/XLSX 适配器。
- [ ] 支持导入预览、字段映射和外部实体映射。
- [ ] 支持写回预览，但不连接未知真实 ERP。
- [ ] 写回模拟包含最终版、合规、外部版本、幂等和运营确认检查。
- [ ] 同步与写回记录可查询。

## 阶段 8：端到端验收

- [ ] 人工创建商品项目流程通过。
- [ ] 标题和 SKU 生成流程通过。
- [ ] 图片分析与美工退回/重提流程通过。
- [ ] 高风险合规阻断流程通过。
- [ ] 三角色权限隔离流程通过。
- [ ] Mock ERP 导入、冲突和写回预览流程通过。
- [ ] 页面刷新或重新登录后数据不丢失。
- [ ] 自动化测试通过并输出测试报告。
- [ ] 提供演示账号、演示数据和本地启动说明。

## MVP 完成定义

只有同时满足以下条件才可以宣布 MVP 完成：

1. 主流程可用，不依赖手工修改数据库。
2. 三个角色权限真实生效。
3. AI 和 ERP 均可使用 Mock 服务完成演示。
4. 高风险、历史版本和写回安全规则得到验证。
5. 有测试结果、演示数据和启动文档。
6. 未完成范围被明确记录，没有用占位按钮伪装为已实现功能。
