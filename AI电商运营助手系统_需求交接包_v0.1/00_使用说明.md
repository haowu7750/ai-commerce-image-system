# AI 电商运营助手系统需求交接包

> 打包版本：V0.1  
> 打包日期：2026-08-10  
> 用途：交给产品、设计、开发人员或代码生成工具，作为系统生成的统一需求输入。

## 1. 阅读顺序

请严格按以下顺序阅读：

1. `01_已确认决策与文档优先级.md`
2. `02_产品需求文档_PRD_v0.1.md`
3. `03_模块功能说明书_v0.1.md`
4. `04_MVP系统蓝图.md`
5. `05_系统生成总指令.md`
6. `06_开发阶段与验收清单.md`

如果使用 Codex 或其他支持项目指令的开发代理，同时读取根目录的 `AGENTS.md`。

## 2. 文档职责

| 文档 | 作用 | 是否具有最终决定权 |
|---|---|---|
| 已确认决策与文档优先级 | 固定角色、权限、范围及冲突处理方式 | 最高 |
| 产品需求文档 PRD | 描述产品目标、用户流程、功能需求和验收场景 | 高 |
| 模块功能说明书 | 补充各模块的输入、输出、规则和异常 | 中 |
| MVP 系统蓝图 | 提供架构、数据、接口和四周制作方案 | 中；技术建议可调整 |
| 系统生成总指令 | 可直接交给代码生成工具执行 | 执行入口 |
| 开发阶段与验收清单 | 控制生成顺序和完成条件 | 交付标准 |

## 3. 冲突处理原则

不同文档如果存在冲突，按以下顺序决定：

`已确认决策 > PRD > 模块功能说明书 > MVP 系统蓝图 > 生成工具自行推断`

不得因为较早文档中出现“单用户演示版”，就删除 PRD 已确定的运营、美工、管理员三类角色。

## 4. 当前交付范围

本压缩包只包含需求、系统设计建议和生成指令，不包含已生成的业务代码。

当前可据此直接开始：

- 页面信息架构和低保真原型生成。
- 数据模型与接口契约细化。
- MVP 项目脚手架及分阶段开发。
- 测试用例与验收脚本编写。

## 5. 使用建议

如果交给代码生成工具，请不要只上传单独一份 PRD。应上传整个压缩包，或解压后让工具从 `00_使用说明.md` 开始读取。

首次生成时应先输出：

1. 对需求的理解摘要。
2. 假设和暂未实现的范围。
3. 页面、数据库、接口和开发阶段清单。
4. 再开始创建代码。

禁止在未声明的情况下自动扩大为订单、采购、仓储、客服或财务系统。
