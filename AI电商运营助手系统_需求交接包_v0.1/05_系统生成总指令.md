# 系统生成总指令

以下内容可以直接交给代码生成工具、开发代理或开发团队作为启动指令。

---

## 可直接使用的生成指令

你需要根据本目录的需求文档，生成“AI 电商运营助手系统”。

开始前必须按顺序完整阅读：

1. `00_使用说明.md`
2. `01_已确认决策与文档优先级.md`
3. `02_产品需求文档_PRD_v0.1.md`
4. `03_模块功能说明书_v0.1.md`
5. `04_MVP系统蓝图.md`
6. `06_开发阶段与验收清单.md`

### 一、需求解释规则

- `01_已确认决策与文档优先级.md` 的决定优先级最高。
- 系统只保留电商运营、美工、管理员三个角色。
- 运营拥有商品内容、美工结果、ERP 写回和上架准备的最终确认权。
- 管理员负责系统配置，不得利用管理员权限绕过运营确认。
- AI 输出不能自动成为最终内容。
- 不得自动发布商品。
- ERP 在 MVP 中完成统一模型、适配器、模拟连接和接口预留；不要伪造真实厂商接口。

### 二、开始编码前先输出

在创建代码前，先输出以下内容供确认：

1. 你对系统目标、三个角色和主流程的理解。
2. MVP 包含与不包含的功能。
3. 页面清单和每个页面的主要操作。
4. 核心数据对象及关系。
5. API 模块清单。
6. 分阶段开发计划。
7. 你采用的默认假设和仍需确认的问题。

如果用户没有提出修改，再进入代码生成。

### 三、推荐实现顺序

1. 项目骨架、环境配置、数据库迁移和基础测试。
2. 用户、角色和权限。
3. 工作台、商品项目和商品信息卡。
4. 图片素材上传和管理。
5. 内容版本、历史记录和统一任务状态。
6. 标题、SKU、合规、图片分析和改图需求模块；先接 Mock AI。
7. 运营与美工任务协作闭环。
8. Prompt、规则和管理员页面。
9. 最终结果、Markdown/CSV 导出。
10. ERPConnector、Mock ERP、字段映射、写回预览和冲突模拟。
11. 端到端测试、演示数据、部署说明和验收报告。

### 四、实现要求

- 前后端接口使用稳定版本前缀，例如 `/api/v1`。
- 所有关键业务数据使用结构化字段，不以聊天记录代替业务数据。
- AI 调用通过统一 Provider，支持 Mock 实现；密钥只从安全配置读取。
- ERP 通过统一 Connector，核心模块不能出现厂商私有字段。
- 所有生成任务保存输入快照、Prompt 版本、模型、输出和错误。
- 所有人工修改产生内容版本，不覆盖历史。
- 商品卡关键字段变化时，受影响结果标记为可能失效。
- 高风险合规内容阻止最终确认和写回。
- ERP 写回必须经过预览、外部版本检查、幂等校验和运营二次确认。
- 管理员、美工和运营权限必须同时在前端和后端校验。
- 提供种子数据，至少包含一个运营、一个美工、一个管理员和三个商品案例。
- 提供可重复执行的测试和清晰的本地启动说明。

### 五、禁止事项

- 不得硬编码 API Key、Token、密码或 ERP 密钥。
- 不得将管理员等同于业务审批人。
- 不得让美工修改商品事实或操作 ERP。
- 不得让 AI 自动确认、写回或发布内容。
- 不得在 MVP 中扩展订单、采购、仓储、客服和财务模块。
- 不得声称合规检查可以替代平台审核。
- 不得用未确认的真实 ERP 字段或接口制作表面可用、实际错误的连接器。

### 六、每个阶段的交付

每完成一个阶段，提供：

- 已完成功能。
- 对应需求编号。
- 数据库或接口变化。
- 自动化测试结果。
- 手工验收方法。
- 未完成项和风险。

不要在未验证上一阶段的情况下连续生成所有功能。

---

## 最终交付目标

交付一个可本地运行、可使用演示数据完成主流程的 MVP：

`运营建项目 → 商品卡 → 图片/标题/SKU → 合规 → 美工任务 → 美工提交 → 运营验收 → 结果导出 → ERP 写回预览模拟`

真实 ERP 在线连接和自动上架不属于本次 MVP 最终交付。
