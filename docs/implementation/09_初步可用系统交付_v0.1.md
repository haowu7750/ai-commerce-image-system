# 初步可用系统交付 v0.1

日期：2026-08-13

## 交付结论

当前系统已完成本地初步可用 MVP，可由运营从项目创建走到商品参考图生图、人工验收、成果导出和 Mock ERP 草稿写回。默认启动为零付费 Mock；真实 Shulicode 模式使用独立启动入口，启动本身不发送请求，只有运营点击生成后才调用 `gpt-image-2`。

## 阶段与功能

### 阶段 0：开发契约

- 七阶段生图、Provider、安全与追踪矩阵已固化在 `docs/implementation/`。
- 固定端口：前端 3100、后端 8100、PostgreSQL 5532。

### 阶段 1：基础能力与权限

- FastAPI、Next.js、JWT、本地演示账号、运营/美工/管理员三角色。
- 服务端 RBAC、项目归属、审计、软删除和管理员恢复。

### 阶段 2：项目与商品事实

- 项目新建、编辑、搜索、平台/店铺/类目筛选。
- 草稿箱、进行中、已完成、已删除。
- 商品信息卡自动保存、字段来源、完整度和缺失影响。

### 阶段 3：素材中心

- 商品原图、主图、竞品图、商品参考图分类上传和预览。
- 用途说明、本次生图选择、引用影响检查和安全归档。

### 阶段 4：内容 AI

- 确定性 Mock 图片结构分析（明确不读取像素）。
- 多候选标题、关键词/长度/风险提示。
- SKU 展示名批量建议，保护价格、库存、商家编码和外部 ID。
- 合规逐段定位、原因和修改建议；高风险不能定稿。

### 阶段 5：美工协作

- 运营派单，美工查看/处理/提问/提交多版。
- 运营通过、部分通过继续修改、返工和取消。
- 美工不能修改商品事实、确认最终内容或操作 ERP。

### 阶段 6：生图、知识与成果

- 生图固定七阶段：产品分析 → 真实场景规划 → 主场景选择 → 保真提示词 → 参考图编辑 → 真实性及缩略图检查 → 运营确认。
- 真实 Provider 使用参考图编辑接口，不是无参考纯文生图。
- 人工检查商品事实、几何/数量、Logo/文字/个性化、缩略图和风险；高风险硬阻断。
- JSON、Markdown、SKU CSV 导出，项目审计时间线，人工沉淀典型案例。

### 阶段 7：Mock ERP

- 统一商品模型、字段映射、导入预览、外部实体映射。
- 草稿写回预览和运营二次确认；外部版本与幂等门禁。
- 永不自动发布，永不修改价格、库存或商家编码。

### 阶段 8：验收

- 后端 34 项、前端 10 项自动化测试通过。
- 完整运营 E2E 通过，自动测试零外部网络/付费调用。
- Next.js 生产构建、Alembic 全新库升级、安全扫描和固定端口启动烟测通过。

## 运行入口

- `Start-System.cmd`：默认 Mock，安全体验。
- `Start-Real-Image.cmd`：Shulicode `gpt-image-2`，仅运营点击生成时发出可能收费的请求。

## 初次体验顺序

1. 运营登录，新建项目或从 Mock ERP 导入。
2. 完成并确认商品卡。
3. 上传商品参考图，勾选本次 AI 生图使用。
4. 内容 AI 生成标题/SKU 建议，在项目详情另存并确认最终版。
5. AI 生图完成七阶段并人工验收。
6. 需要精修时创建美工任务，切换美工账号提交，再由运营验收。
7. 到结果汇总导出成果；需要时执行 Mock ERP 草稿写回。

## 剩余风险和非交付范围

- Shulicode 配置存在性、模型锁定和 MockTransport 契约已验证，但未由自动化测试发起真实付费烟测，也没有真实输出图的人工视觉验收证据。因此不能宣称中转站实图链路已验收成功。
- 图片分析为确定性 Mock，当前不读取图片像素；真实视觉分析仍是后续能力。
- 当前本地上传使用 data URL，适合初步体验，不适合生产大文件；生产需对象存储。
- ERP 仅本地 Mock，未连接未知真实厂商。
- 正式 PostgreSQL 部署需在目标环境执行 `alembic upgrade head`，并关闭体验账号和自动建表。
- Starlette/httpx 与一个 422 常量有弃用警告，不影响当前业务结果，后续依赖升级时处理。
