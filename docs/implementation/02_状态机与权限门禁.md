# 商品图/场景图状态机与权限门禁

> 文档类型：阶段 0 开发契约  
> 日期：2026-08-10  
> 关联规格：`01_MVP生图模块规格_v0.2.md`  

## 1. 规则

状态只能通过本文列出的动作迁移。前端可以隐藏或禁用按钮，但后端必须在每次写操作时重新计算角色、输入版本、合规、质量和副作用门禁。

| 需求编号 | 规范性要求 | 验收条件 |
|---|---|---|
| IMG-STATE-001 | 工作流状态、候选状态、质量状态和合规状态分别保存，不用一个字段混合表达。 | 数据 Schema 存在四组独立枚举；组合查询可区分“生成成功但 QA 失败”和“QA 通过但合规阻断”。 |
| IMG-STATE-002 | 非法迁移返回 `409 INVALID_STATE_TRANSITION`，不修改任何业务记录。 | 对每个状态至少执行一个非法迁移测试，事务前后业务字段一致，仅新增拒绝审计事件。 |
| IMG-STATE-003 | 所有迁移使用乐观锁版本号；旧版本请求不能覆盖新状态。 | 两个并发请求携带同一 `expected_version` 时仅一个成功，另一个返回 `409 WORKFLOW_VERSION_CONFLICT`。 |
| IMG-STATE-004 | 归档项目不能创建或推进生图任务，恢复项目后才可继续。 | 归档项目调用任一推进接口返回 `PROJECT_ARCHIVED`；恢复后从原有效状态继续。 |

## 2. 工作流状态

| 状态 | 含义 | 允许的下一步 |
|---|---|---|
| `draft` | 工作流已创建，输入尚未完成 | 产品类型分析、取消 |
| `product_type_ready` | 产品类型分析有效 | 真实场景规划、重做分析、取消 |
| `scene_plan_ready` | 场景候选有效，等待运营选择 | 选择主场景、重做规划、取消 |
| `hero_scene_selected` | 运营已选择一个主场景 | 构建保真 Prompt、更换主场景、取消 |
| `prompt_ready` | Prompt 已通过事实与生成前合规检查 | 请求生成/编辑、编辑 Prompt、取消 |
| `generating` | 图像 Provider 正在处理 | 候选就绪、生成失败 |
| `candidate_ready` | 候选文件已校验并落库 | 开始质量/合规检查 |
| `qa_pending` | 正在执行真实性、缩略图和候选合规检查 | 待运营确认、QA 失败、合规阻断 |
| `qa_failed` | 存在高严重度真实性/缩略图问题 | 修改 Prompt 或基于参考图重新编辑、取消 |
| `compliance_blocked` | 存在未处理高风险或中风险 | 修改 Prompt/候选后复检、取消 |
| `awaiting_operator_confirmation` | 当前候选通过全部确认门禁 | 运营确认、运营拒绝、重新生成 |
| `operator_confirmed` | 运营确认了模块内版本 | 新建派生版本、因上游变化失效 |
| `generation_failed` | Provider 失败且未产生新候选 | 重试、返回 Prompt、取消 |
| `stale` | 上游事实或版本变化导致下游失效 | 从最早受影响阶段重新执行、取消 |
| `cancelled` | 用户取消，历史保留 | 无；新建工作流 |

## 3. 合法迁移契约

| 需求编号 | 起始状态 → 动作 → 目标状态 | 角色与前置条件 | 验收条件 |
|---|---|---|---|
| IMG-TR-001 | `draft` → `analyze_product_type` → `product_type_ready` | 运营；事实快照和合格产品参考图存在；文本/视觉 Mock 输出通过 Schema。 | 成功后保存输入快照和分析版本；缺输入时状态仍为 `draft`。 |
| IMG-TR-002 | `product_type_ready` → `plan_real_scenes` → `scene_plan_ready` | 运营；无未解决事实冲突。 | 产生 1–3 个结构化场景，0 个或超过 3 个时迁移失败。 |
| IMG-TR-003 | `scene_plan_ready` → `select_hero_scene` → `hero_scene_selected` | 运营；选择理由非空且场景属于当前规划版本。 | 仅一个场景为当前主场景并记录选择审计。 |
| IMG-TR-004 | `hero_scene_selected` → `build_fidelity_prompt` → `prompt_ready` | 运营；Prompt 事实检查通过且无生成前高风险。 | Prompt 含锁定项、负向约束、参考图与快照版本。 |
| IMG-TR-005 | `prompt_ready` → `request_generate_or_edit` → `generating` | 运营；参考图哈希仍有效；模型允许；幂等键有效。 | 创建一个任务；重复幂等键返回同一任务。 |
| IMG-TR-006 | `generating` → `provider_succeeded` → `candidate_ready` | 系统；输出 MIME、尺寸、大小和哈希校验通过。 | 新候选默认未确认、未发布、未写回。 |
| IMG-TR-007 | `generating` → `provider_failed` → `generation_failed` | 系统；错误已映射并记录。 | 旧成功候选不变，错误标记是否可重试。 |
| IMG-TR-008 | `candidate_ready` → `start_checks` → `qa_pending` | 系统；候选文件和输入版本有效。 | 创建不可变质量报告和合规报告任务。 |
| IMG-TR-009 | `qa_pending` → `checks_passed` → `awaiting_operator_confirmation` | 系统；无高严重度 QA 失败、无关键 `unknown`、无未处理高/中风险。 | 确认门禁快照完整，确认按钮仅运营可见。 |
| IMG-TR-010 | `qa_pending` → `qa_rejected` → `qa_failed` | 系统；存在高严重度 QA 失败或关键 `unknown`。 | 报告逐项给出证据和建议，确认接口拒绝。 |
| IMG-TR-011 | `qa_pending` → `risk_blocked` → `compliance_blocked` | 系统；存在未处理高风险或中风险。 | 风险列表可定位具体 Prompt/候选区域，确认接口拒绝。 |
| IMG-TR-012 | `awaiting_operator_confirmation` → `confirm` → `operator_confirmed` | 运营；全部门禁在事务内重检通过。 | 仅该候选成为当前模块确认版本；不产生发布、ERP 或其他内容最终化事件。 |
| IMG-TR-013 | `awaiting_operator_confirmation` → `reject` → `prompt_ready` | 运营；拒绝原因非空。 | 候选标记拒绝但不删除，后续必须产生新候选。 |
| IMG-TR-014 | `generation_failed` → `retry` → `generating` | 运营；错误可重试；使用同一业务幂等根和新尝试号。 | 重试次数递增，不复制业务任务。 |
| IMG-TR-015 | 任一非终态 → `upstream_changed` → `stale` | 系统；事实、参考集、主场景或 Prompt 当前版本变化。 | 原结果只读保留，所有确认入口失效。 |
| IMG-TR-016 | 任一非终态 → `cancel` → `cancelled` | 运营；运行中任务只发取消意图，不伪造 Provider 已取消。 | 历史保留；迟到结果隔离为不可确认候选。 |

## 4. 候选、质量与合规子状态

| 需求编号 | 状态规则 | 验收条件 |
|---|---|---|
| IMG-CAND-001 | 候选状态为 `created`、`checking`、`reviewable`、`rejected`、`operator_confirmed`、`stale`；新候选只能从 `created` 开始。 | Provider 返回后检查默认值；不存在直接写入 `operator_confirmed` 的数据路径。 |
| IMG-QA-001 | QA 状态为 `pending`、`passed`、`failed`、`invalidated`；报告发布后不可人工改写。 | 任何角色 PATCH 报告均返回 405；重新检查创建新报告。 |
| IMG-COMP-001 | 合规状态为 `unchecked`、`checking`、`clear`、`medium_open`、`medium_resolved`、`high_open`、`invalidated`。 | 风险变化会创建新报告；旧报告保留规则版本和候选哈希。 |
| IMG-COMP-002 | `high_open` 无豁免路径；必须修改输入或候选并复检到不存在高风险。 | 管理员、运营和组合角色均不能直接把 `high_open` 改为已处理。 |
| IMG-COMP-003 | `medium_open` 必须修改复检，或由运营记录保留理由后变为 `medium_resolved`；低风险只提示并留痕。 | 中风险无理由时确认失败；理由包含操作者、时间、内容和报告版本。 |

## 5. 角色权限矩阵

`运营`、`美工`、`管理员` 是唯一业务角色。多角色权限采用并集，但“运营确认”必须显式具备运营角色；管理员身份不会隐含该权限。

| 操作 | 运营 | 美工 | 管理员 |
|---|---|---|---|
| 创建工作流、选择产品参考图 | 允许 | 禁止 | 禁止 |
| 编辑商品事实 | 允许，沿用商品卡权限 | 禁止 | 禁止；需同时具备运营角色 |
| 查看场景规划、Prompt、候选与报告 | 允许 | 仅限分配任务必要内容 | 系统排错可读，默认不含业务确认动作 |
| 选择主场景、确认 Prompt | 允许 | 可留言建议，不可推进 | 禁止；需同时具备运营角色 |
| 请求生成/编辑、重试 | 允许 | MVP 禁止 | 禁止；需同时具备运营角色 |
| 上传美工版本 | 允许 | 仅限分配给自己的美工任务 | 禁止 |
| 修改 QA/合规报告 | 禁止直接修改 | 禁止 | 禁止直接修改；可管理规则新版本 |
| 确认/拒绝候选 | 仅运营允许 | 禁止 | 禁止；需同时具备运营角色 |
| 发布、ERP 写回 | 本模块无此权限 | 禁止 | 禁止 |
| 配置 Provider/Prompt/规则 | 禁止全局配置 | 禁止 | 允许，但不能改变历史任务输入 |

| 需求编号 | 权限要求 | 验收条件 |
|---|---|---|
| IMG-RBAC-001 | 所有业务接口必须以服务端有效角色和对象范围授权，不能信任客户端提交的角色。 | 篡改请求体角色字段不提升权限；JWT/会话无权限时返回 403。 |
| IMG-RBAC-002 | 美工只能读取分配任务所需字段和素材，不能读取成本、密钥、全局日志或未分配项目。 | 使用两个美工和两个任务做对象级越权测试，交叉访问全部被拒绝。 |
| IMG-RBAC-003 | 美工对商品事实的任何写入都必须被拒绝并审计。 | 覆盖 UI、API 和批量接口的负向测试，事实版本均不变化。 |
| IMG-RBAC-004 | 仅管理员可以配置 Provider 路由、Prompt 和规则版本，但管理员不能确认业务候选。 | 仅管理员配置成功、确认失败；运营配置失败、确认成功。 |
| IMG-RBAC-005 | 运营确认必须在同一事务内校验角色、对象范围、状态、版本、QA 与合规。 | 在检查通过后、确认前制造上游变化，确认返回冲突且不写入部分状态。 |

## 6. 硬门禁

| 需求编号 | 门禁 | 拒绝码 | 验收条件 |
|---|---|---|---|
| IMG-GATE-001 | 产品参考图存在、可读、属于当前项目且哈希匹配。 | `REFERENCE_IMAGE_REQUIRED` / `REFERENCE_VERSION_STALE` | 缺失、跨项目或被替换的参考图均不能生成或确认。 |
| IMG-GATE-002 | 七阶段顺序与当前状态合法。 | `INVALID_STATE_TRANSITION` | 跳步请求不创建下游记录。 |
| IMG-GATE-003 | 商品事实、参考集、场景和 Prompt 都是当前版本。 | `INPUT_VERSION_STALE` | 任一旧版本阻断生成与确认。 |
| IMG-GATE-004 | 图像模型严格等于 `gpt-image-2`；无隐式回退。 | `PROVIDER_MODEL_NOT_ALLOWED` | 非允许模型和省略后被篡改的模型均不发起外部请求。 |
| IMG-GATE-005 | 真实性与缩略图检查通过。 | `IMAGE_QUALITY_BLOCKED` | 高严重度失败或关键 `unknown` 阻断确认。 |
| IMG-GATE-006 | 无未处理高风险；中风险已处理或记录理由。 | `HIGH_RISK_BLOCKED` / `MEDIUM_RISK_UNRESOLVED` | 风险夹具对全部角色组合均生效。 |
| IMG-GATE-007 | 确认者具备运营角色且对象在其业务范围。 | `OPERATOR_ROLE_REQUIRED` | 美工、仅管理员和其他项目运营不能确认。 |
| IMG-GATE-008 | 生成与确认不得触发自动最终化、发布或 ERP 写回。 | `SIDE_EFFECT_FORBIDDEN` | 事件断言和数据库断言均为零副作用。 |

## 7. 失效传播

| 需求编号 | 上游变化 | 必须失效的下游 | 验收条件 |
|---|---|---|---|
| IMG-INV-001 | 商品关键事实或产品参考集变化 | 类型分析、场景、Prompt、候选、QA、合规、确认状态 | 历史确认版本保留但不再是当前可交付版本。 |
| IMG-INV-002 | 产品类型分析变化 | 场景及其全部下游 | 从场景规划重新开始。 |
| IMG-INV-003 | 主场景变化 | Prompt、候选、QA、合规、确认状态 | 新场景不能复用旧 Prompt 检查结果。 |
| IMG-INV-004 | Prompt 变化 | 候选、QA、合规、确认状态 | 旧候选仍可对比但不可确认。 |
| IMG-INV-005 | 候选文件或哈希变化 | QA、合规、确认状态 | 篡改检测立即阻断确认并记录安全事件。 |

## 8. 审计契约

| 需求编号 | 审计要求 | 验收条件 |
|---|---|---|
| IMG-AUD-001 | 每个状态迁移记录 `actor_id`、有效角色、动作、对象、前后状态、输入/输出版本、`request_id`、结果和 UTC 时间。 | E2E 时间线可按顺序重建七阶段，无缺失迁移。 |
| IMG-AUD-002 | Provider 调用记录模型、模式、幂等键、参考图哈希摘要、Provider 请求 ID、耗时和结果；不得记录密钥或完整敏感请求。 | 日志扫描无 Token/Secret；仍可由审计字段定位一次调用。 |
| IMG-AUD-003 | 权限、合规、质量、版本和模型门禁的拒绝也必须记录。 | 每类门禁负向测试都产生一个 `denied` 审计事件并包含稳定原因码。 |
| IMG-AUD-004 | 历史状态、报告和确认记录不可原地删除；归档不等于删除。 | 普通业务 API 无物理删除路径；归档后审计仍可查询。 |
