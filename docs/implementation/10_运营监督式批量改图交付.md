# 运营监督式批量改图交付

日期：2026-08-17

## 范围决定

用户要求参考 `D:\Claude code\02_电商生图系统` 的批量改图能力，加入当前系统。参考项目包含批量替换、自定义批量、批量改尺寸、定时执行和结果打包。

当前项目既有 `IMG-SCOPE-004` 禁止“批量无人值守生图”。本次用户新增要求覆盖“没有批量功能”的旧范围，但没有授权无人值守自动执行。因此交付前三种人工发起的批量操作、逐图进度和结果打包，不交付定时执行。该取舍保留三角色、商品参考图事实源、运营确认、高风险阻断、无自动发布和无 ERP 图片写回规则。

## 已实现能力

### 三种模式

1. `replace_product`：同一商品参考图替换到 1–10 张场景图。
2. `custom_edit`：同一运营修改说明应用到 1–10 张图片。
3. `resize`：将 1–10 张图片重排到统一目标尺寸。

三种模式均要求：

- 操作者拥有运营角色并拥有项目。
- 项目不是已删除或已完成状态。
- 商品信息卡已由运营确认。
- 至少一张未归档、带哈希的商品参考图。
- 所有待处理图片属于当前项目、未归档且带文件哈希。
- 每张源图只产生一个候选；相同幂等键不重复调用 Provider。

### 数据与状态

- `batch_image_tasks` 保存模式、Provider、模型、保真 Prompt、输入素材 ID、商品卡/文件哈希快照、进度、错误和幂等键。
- `batch_image_items` 保存逐图状态、候选、错误、QA、合规、不可覆盖的人工检查、运营确认和最终素材关联。
- 父任务支持 `queued / running / succeeded / partial / failed / cancelled`。
- 子项支持 `queued / running / succeeded / failed`。
- 某张失败不删除其他成功候选；全部失败时父任务失败。

数据库迁移：`0005_batch_image_tasks`。本地体验的自动建表会在重启时创建新表；正式 PostgreSQL 执行 `alembic upgrade head`。

## 人工门禁

成功候选不是最终图。运营必须逐图记录：

- 商品事实是否一致。
- 几何、比例与数量是否一致。
- Logo、文字和个性化信息是否一致。
- 缩略图主体是否可读且无关键裁切。
- 合规风险及说明；中风险必须填写保留理由。

人工检查记录保存后不可覆盖。真实性/缩略图失败或高风险候选不能确认。确认只创建项目内 `generated_image` 素材和审计事件，不触发发布或 ERP。ZIP 只包含已确认且本地可打包的结果。

## 权限

- 运营：创建、查看、检查、确认和下载自己的项目批量任务。
- 美工：无批量改图页面和接口权限。
- 仅管理员：无业务批量改图或确认权限；需要参与时必须同时拥有运营角色。
