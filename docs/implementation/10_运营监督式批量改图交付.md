# 运营监督式批量图片工具交付

日期：2026-08-17

## 参考与范围

本轮按用户指定的 `D:\Claude code\01_电商生图系统项目\screenshots` 及其只读拆解文档重新设计批量图片模块。参考截图呈现六个独立工具、顶部任务创建栏、状态标签、任务历史、进度、结果图、批量下载与删除。

当前项目的人工确认和安全规则优先级更高，因此保留以下差异：

- 不复制品牌、Logo、积分或收费体系，只参考功能结构与交互组织。
- 不提供截图中的定时无人值守执行；当前只在运营点击“创建任务”后立即执行。
- AI 输出先作为候选图，运营逐图检查并确认后才保存为项目素材。
- 高风险或真实性检查失败的候选图不能确认、下载为最终结果、发布或写回 ERP。
- Provider 模型由系统配置契约固定，界面展示真实运行模型，不提供不可用的假模型选项。

## 六个独立工具

1. `scene_replace` 批量场景替换：1 张商品参考图 + 1–10 张场景图。商品参考图是商品外观事实源，场景图只提供环境、构图和光照。
2. `pattern_extract` 批量印花提取：选择印花载体、输出尺寸和 1–10 张商品原图，校正透视并生成平面印花候选。
3. `resize` 批量改尺寸：1–10 张图片，支持 1:1、3:4、4:3、3:2、2:3、16:9、9:16，按目标尺寸智能重排，不做简单拉伸或关键裁切。
4. `buyer_show` 批量买家秀：1 张商品参考图 + 1–10 张晒单场景，生成自然生活化候选并禁止虚假使用效果。
5. `angle_fission` 批量角度裂变：填写拍摄主体、整体图数量和细节图数量；每张产品场景图按镜头计划展开多个子任务，最多 5 张输入。
6. `custom_edit` 自定义批量：固定参考图可选、参考图一必填、参考图二可选并逐行等量配对；同一提示词应用到每一行。

旧版 `replace_product` 枚举仅为读取已存在任务保留，不再作为前端新建入口。

## 页面与交互

- `/batch-image` 是六个工具的入口卡片页。
- `/batch-image/[mode]` 是各工具的独立创建与历史页。
- 创建区提供项目、模式专属字段、上传、从项目素材选择、真实 Provider/模型展示和立即创建。
- 历史区提供全部、处理中、已完成、失败筛选；显示输入缩略图、模型、状态、进度、时间、结果缩略图与操作。
- 支持单任务或多任务下载；ZIP 只打包已经过运营确认的本地结果。
- “删除”是软删除，运行中/排队中任务不可删除，审计和结果链不物理清除；后端提供恢复接口。
- 任务详情保留输入/候选对照、四项真实性检查、合规分级、中风险理由和运营最终确认。

## 数据与执行

- 沿用 `batch_image_tasks` 与 `batch_image_items`，模式专属参数保存在 `options_json`，无需新增表迁移。
- 输入快照同时记录公共参考图、主输入图和配对参考图的素材 ID 与 SHA-256。
- 角度裂变按“输入图 × 整体/细节镜头数量”建立子项，并为每项记录镜头类型和序号。
- 每张失败不删除其他成功候选；父任务支持 `queued / running / succeeded / partial / failed / cancelled`。
- 相同幂等键不会重复调用 Provider；商品卡或输入图片变化后，旧候选不能继续检查或确认。
- 自动化测试只用 Mock Provider，不发起真实网络或付费图片请求。

## 权限与边界

- 运营：创建、查看、检查、确认、下载和软删除自己的项目任务。
- 美工：无批量图片工具页面和接口权限。
- 仅管理员：不自动拥有业务批量改图或确认权；需要参与时必须同时具有运营角色。
- 所有创建、执行、失败、检查、确认、软删除和恢复动作写入审计。

## 仍未实现

- 定时任务、持久化队列、失败行单独重试和对象存储尚未实现，界面不提供伪按钮。
- 本地体验仍以应用进程后台任务执行；进程重启可能中断运行中任务。
- 真实 Shulicode 能力必须另做无敏感值的连通性诊断和人工视觉验收，Mock 通过不能证明真实 Provider 可用。
